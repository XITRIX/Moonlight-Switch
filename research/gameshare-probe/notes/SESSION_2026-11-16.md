# Autonomous continuation, 2026-11-16

## Outcome and stopping condition

**GameShare hosting is still not working.** Seven complete preparation attempts
in a fresh probe session returned the same native result, **0x2fab1f**
(module 287, description 6101). No valid matchmaking argument was returned;
no hosting applet, advertisement, guest connection or image stream was started.

The user authorized sustained research with the running probe and public web
references, while preserving the earlier requirement that HEN and RO remain
unchanged. All new native code ran in the probe's own JIT allocation. No HEN/RO
code or file, title metadata, parental setting, save or boot file was changed.
No Nintendo-server connection was initiated. The installed NRO remains 0.3.1.

This pass stopped at an evidence boundary, rather than expanding opaque-field
guesses: the complete service validation and CMIF writers are absent from the
public reconstructions inspected; the active probe has neither a loader session
nor debugger syscall hints with which to read the missing executable code.
Further repetition of these configurations would not identify the cause.
This is a limit of the available environment and references, not proof that
homebrew GameShare hosting is impossible.

## Public-source and artifact conclusions

- [Contract audit](contract-investigation.md): the reconstructed SDK explicitly
  recognizes 6101, but supplies no semantic name. Existing counts/flags meet its
  recovered API checks. Commands507/509 belong after the applet. System-service
  metadata and emulator stubs do not supply an alternate proven host contract.
- [Metadata audit](metadata-requirements.md): no supported GameShare enable flag
  or ARP registration prerequisite was found. NACP byte0x3569 is named
  StreamPlaySaveDataKeyType, with unknown semantics. No metadata was changed.
- [Read-only access audit](readonly-code-access.md): the old ordinary-FS failure
  0xc56ee202 has FS module2/description6001, within the public InvalidArgument
  range. It is not evidence of permission denial. Public ordinary-FS enums omit
  Code type0; dedicated fsp-ldr remains the documented code route.

The original exact installed ELF/NRO were inspected on PC with cross-nm and
objdump. The own-process hint probe checks both its openService anchor and
32 bytes covering envIsSyscallHinted's ADRP/ADD/LDR address calculation before
reading the 24-byte mask. This qualification applies only to the recorded
installed runtime; it must be regenerated for another NRO. These artifact
observations came from ordinary local tools, not a REA decompiler result.
REA reported no configured native decompiler; no server binary was available
to analyze in any event.

## Tools and validation

  initialized type/mode readback, and accepts a bounded 16-byte experiment
  input. Existing 2–5-byte inputs remain supported. New input format:
  `<8BIHH`: type, mode, newer-command, display, zero, frame-rate, zero, zero,
  flags, feature, other. All actual new tests used frame-rate/feature/other=0.
  Parental communication checks remain mandatory for every flags variation.

  diagnostics. The latter is guarded for the original installed 0.3.1 only.

  submission without POST. Session, next job number, image size, entry point

## What would unlock another productive pass

One of these would provide materially new evidence:

1. A lawful, decompressed Chat executable from this firmware, or the relevant
   service-side validation disassembly, to identify the actual 6101 branch.
2. A suitable game SDK/module with the real StreamPlay CMIF writer bodies, or
   a captured known-good native host call sequence/configuration. A cartridge
   being present alone does not make its executable accessible to this probe.
3. An independently available read-only CodeFS/loader provider, supplied outside
   HEN/RO, that can use its own valid loader session. None is presently exposed.

The running probe is idle, unpoisoned, with no retained test service objects,
raw-handle registry entries, work buffers or guest display/layer. No guest
connection attempt is warranted until matchmaking returns valid arguments and
an actual host advertisement is established.
